### 접근하는 방법(대부분의 공부 방법에 적용 가능)

AI를 쓰는 방법 → AI를 잘 쓰는 방법 → 그리고 점점 더 잘 쓰는 방법

이런식으로 고민

### 중요 습관

- 공식 문서 읽기
    
    - 가장 최신의 기술을 만든사람의 의도대로 작성되어있음
    - → 깊이 있게 읽는 것을 습관화 해야 함
        - 깊이 있게 읽는다
            - = 도구를 만든 장이느이 철학을 이해하는 것
            - = 설계 의도와 원리를 파악하는 것
            - = 최신 업데이트를 가장 먼저 아는 것
    - 블로그 글 = 이렇게 하면 된다
    - 공식문서 = 왜 이렇게 설계 했는가
- AI의 공식문서란?
    
    - Anthropic, OpenAI, Google gemini등의 공식 문서 확인
        - 직접 작성한 프롬프트 엔지니어링 가이드가 있음.
    - 모든 공식 문서중 하나만 본다면 = Anthropic
        - 이해 쉬움, 읽기 쉬움, 그냥 좋음

### 프롬프트 엔지니어가 작성한 공식 가이드북에서 가장 먼저 강요한 것

- 프롬프트 엔지니어링 이전에 해야할 것들을 작성

```
1. 사용 사례에 대한 성공 기준의 명확한 정의
2. 해당 기준에 대해 경험적으로 테스트 할 수 있는 방법들
3. 개선하고자 하는 첫 번째 초안 프롬프트

그렇지 않다면, 먼저 이를 확립하는 데 시간을 투자할 것을 권장한다.
```

- 성공 기준 :
    
    - 모호한 기준 : AI가 잘 대답하면 성공 , 결과가 괜찮으면 성공
    - 명확한 기준 : TypeScript 타입 정의 100% 포함, 실행가능한 코드
- 경험적으로 테스트할 방법
    
    - 테스트 없는 프롬프트
        - 한 번 써보고 → 됐다!→ 다음에 안 됨 → ai 이상해
    - 테스트 있는 프롬프트
        - 10개의 샘플로 테스트 → 7개 성공 → 실패 3개 분석 → 개선
- 개선하고자 하는 초안 프롬프트
    
    - 완벽주의자 함정
        - 처음부터 완벽한 프롬프트를 작성해야지 → 시작 못함
    - 반복 개선 접근
        - v1.0 → v1.1 → v2.0 이런식으로 버전 업
- 기법을 익히는 것보다 의도를 설계하는 것이 먼저다
    
    - pre-prompting : 프롬프트를 작성하기 전 의도와 사고를 먼저 설계하는 과정
        - Define - 정의하기
            - 내가 원하는 성공은 무엇인가
        - Test - 검증하기
            - 어떻게 측정ㅎ고 테스트할 것인가
        - Iterate - 개선하기
            - 실패에서 무엇을 배울 것인가
- 올바른 문제를 정의하고, 의도를 설계하여 입력
    
- 작성한 프롬프트 리뷰 습관
