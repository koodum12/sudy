### 스프린트

gstack은 도구 모음이 아니라 프로세스입니다. 스킬은 스프린트 진행 순서대로 실행됩니다.

**생각 → 계획 → 구축 → 검토 → 테스트 → 출시 → 성찰**

각 기술은 다음 단계로 이어집니다. `/office-hours`설계 문서를 작성하면 해당 문서를 `/plan-ceo-review`읽고, `/plan-eng-review`테스트 계획을 작성하면 해당 `/qa`문서를 읽고, `/review`버그를 찾아내고 `/ship`수정되었는지 확인합니다. 모든 단계가 이전 단계를 알고 있기 때문에 어떤 것도 누락되지 않습니다.

| 기능                       | 담당 전문의           | 그들이 하는 일                                                                                                                                    |
| ------------------------ | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `/office-hours`          | **YC 사무실 운영 시간** | 여기서 시작하세요. 코드를 작성하기 전에 제품을 재구성하는 6가지 핵심 질문입니다. 기존의 관점을 재고하게 하고, 전제에 의문을 제기하며, 다양한 구현 대안을 제시합니다. 설계 문서는 모든 후속 기술에 영향을 미칩니다.                  |
| `/plan-ceo-review`       | **CEO/창립자**      | 문제를 다시 생각해 보세요. 요청 내용 속에 숨겨진 10점 만점짜리 제품을 찾아보세요. 확장, 선택적 확장, 범위 유지, 축소의 네 가지 모드가 있습니다.                                                      |
| `/plan-eng-review`       | **엔지니어링 매니저**    | 아키텍처, 데이터 흐름, 다이어그램, 예외 상황 및 테스트를 확정합니다. 숨겨진 가정을 드러내도록 합니다.                                                                                 |
| `/plan-design-review`    | **수석 디자이너**      | 각 설계 요소를 0~10점으로 평가하고, 10점이 어떤 모습인지 설명한 다음, 목표에 도달하도록 설계도를 수정합니다. AI 기반 경사 감지 기능이 있으며, 설계 선택 항목당 하나의 AskUserQuestion을 통해 상호작용할 수 있습니다.      |
| `/design-consultation`   | **디자인 파트너**      | 완벽한 디자인 시스템을 처음부터 구축합니다. 시장 상황을 조사하고, 창의적인 시도를 제안하며, 현실적인 제품 목업을 제작합니다.                                                                     |
| `/review`                | **수석 엔지니어**      | CI를 통과했지만 프로덕션 환경에서 심각한 오류를 일으키는 버그를 찾아냅니다. 명백한 버그는 자동으로 수정하고, 코드 완성도가 부족한 부분을 표시합니다.                                                       |
| `/investigate`           | **디버거**          | 체계적인 근본 원인 디버깅. 철칙: 조사 없이는 수정도 없다. 데이터 흐름을 추적하고, 가설을 검증하며, 세 번의 수정 시도가 실패하면 중단한다.                                                           |
| `/design-review`         | **코딩하는 디자이너**    | /plan-design-review와 동일한 감사를 수행한 후 발견된 사항을 수정합니다. 원자적 커밋이 가능하며, 수정 전후 스크린샷이 제공됩니다.                                                          |
| `/qa`                    | **QA 리드**        | 앱을 테스트하고, 버그를 찾고, 원자적 커밋으로 수정하고, 다시 검증하세요. 모든 수정 사항에 대해 회귀 테스트를 자동으로 생성합니다.                                                                 |
| `/qa-only`               | **QA 리포터**       | /qa와 동일한 방법론을 사용하지만, 코드 변경 없이 버그 보고서만 작성합니다.                                                                                                |
| `/cso`                   | **최고 보안 책임자**    | OWASP Top 10 + STRIDE 위협 모델. 노이즈 제로: 17개의 오탐 제외, 8/10 이상의 신뢰도 검증, 독립적인 탐지 결과 검증. 각 탐지 결과에는 구체적인 공격 시나리오가 포함되어 있습니다.                         |
| `/ship`                  | **릴리스 엔지니어**     | 메인 브랜치 동기화, 테스트 실행, 코드 커버리지 감사, 푸시, PR 열기. 테스트 프레임워크가 없으면 부트스트랩 기능도 제공합니다.                                                                  |
| `/land-and-deploy`       | **릴리스 엔지니어**     | PR을 병합하고, CI를 기다린 후 배포하고, 프로덕션 환경에서 정상 작동하는지 확인합니다. "승인됨"에서 "프로덕션 환경에서 확인됨"까지 단 하나의 명령으로 완료됩니다.                                             |
| `/canary`                | **SRE**          | 배포 후 모니터링 루프입니다. 콘솔 오류, 성능 저하 및 페이지 오류를 감시합니다.                                                                                              |
| `/benchmark`             | **성능 엔지니어**      | 기준 페이지 로드 시간, 코어 웹 바이탈(Core Web Vitals) 및 리소스 크기를 측정합니다. 모든 PR에 대해 전후 비교를 수행합니다.                                                            |
| `/document-release`      | **기술 문서 작성자**    | 방금 배포한 버전에 맞춰 모든 프로젝트 문서를 업데이트합니다. 오래된 README 파일을 자동으로 감지합니다.                                                                               |
| `/retro`                 | **엔지니어링 매니저**    | 팀 전체의 상황을 고려한 주간 회고. 개인별 분석, 연속 배송 실적, 테스트 진행 상황 추세, 성장 기회 등을 다룹니다. `/retro global`모든 프로젝트 및 AI 도구(Claude Code, Codex, Gemini)를 통합하여 실행합니다. |
| `/browse`                | **QA 엔지니어**      | 실제 크롬 브라우저, 실제 클릭, 실제 스크린샷. 명령당 약 100ms.                                                                                                    |
| `/setup-browser-cookies` | **세션 관리자**       | 실제 브라우저(Chrome, Arc, Brave, Edge)에서 쿠키를 가져와 헤드리스 세션에 통합합니다. 인증된 페이지를 테스트합니다.                                                                |
| `/autoplan`              | **검토 파이프라인**     | 단 한 번의 명령으로 완벽한 검토를 거친 계획을 실행합니다. CEO → 디자인 → 엔지니어링 검토 과정을 인코딩된 의사 결정 원칙에 따라 자동으로 실행합니다. 최종적으로는 사용자 승인을 위해 맛 관련 결정 사항만 표시합니다.               |

### 전동 공구

[](https://github.com/garrytan/gstack#power-tools)

|기능|이 제품의 기능은 무엇인가요?|
|---|---|
|`/codex`|**Second Opinion** — OpenAI Codex CLI를 통한 독립적인 코드 검토. 세 가지 모드: 검토(통과/실패 여부 확인), 적대적 챌린지, 공개 상담. 두 가지 모드가 모두 `/review`실행 `/codex`된 경우 모델 간 분석 가능.|
|`/careful`|**안전 가드레일** — 파괴적인 명령(rm -rf, DROP TABLE, force-push)을 실행하기 전에 경고합니다. 활성화하려면 "조심하세요"라고 말하세요. 경고를 무시할 수도 있습니다.|
|`/freeze`|**편집 잠금** — 파일 편집을 특정 디렉터리로 제한합니다. 디버깅 중에 범위를 벗어난 실수로 인한 변경을 방지합니다.|
|`/guard`|**완벽한 안전성** — `/careful`+ `/freeze`한 번의 명령으로. 생산 작업에 필요한 최고의 안전성.|
|`/unfreeze`|**잠금 해제** — `/freeze`경계를 제거하세요.|
|`/setup-deploy`|**배포 구성 도구** — 일회성 설정입니다 `/land-and-deploy`. 플랫폼, 프로덕션 URL 및 배포 명령을 자동으로 감지합니다.|
|`/gstack-upgrade`|**셀프 업데이터** — gstack을 최신 버전으로 업그레이드합니다. 글로벌 설치와 벤더링된 설치를 감지하고, 두 설치를 모두 동기화하며, 변경 사항을 표시합니다.|
